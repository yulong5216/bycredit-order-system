## 第一部分 · 工程现状交待

### 1.1 项目是什么

越南手机分期 + 回收业务的订单管理系统。Web 后台（业务员录单/初审/终审/财务/门店管理）+ 客户账单页（并入 Zalo 小程序 H5）。目标：替换现有"Excel + Google Sheets 手工贷后"的工作流。

### 1.5 已定版的核心业务规则（全部经用户确认，不要偏离）

1. **两阶段策略**：第一阶段核心系统 + mock 演示闭环；第二阶段接真实 VietQR + MobiFone。**mock 与真实 provider 必须实现同一内部接口，切换 provider 不动核心业务代码。**
2. **状态机（14 态）**：draft → pending_first → pending_customer_sign → (回 pending_first) → pending_final → pending_finance → pending_payout → repaying → closed；驳回 rejected_first/rejected_final；取消 cancelled。**签约成功和 MDM 绑定后一律保持 pending_first，初审必须人工点击"通过"才进终审——用户明确要求，禁止任何自动流转**（终审通过自动送财务是用户默认接受的）。
3. **订单号格式**：`L + YYYYMMDD + 9位毫秒时间戳`（例 L20261123441291520）。没有时分秒。
4. **编辑限制**：初审通过后（pending_final 及之后）不可再编辑客户资料；允许编辑的状态仅 draft/pending_first/rejected_first/pending_customer_sign。
5. **账单**：放款成功自动生成 N 期账单；等额算法见 utils/schedule.js；利率字段 rateBps 前端隐藏仅后台反推。
6. **权限**：admin 无 createOrder（新建录单是业务员功能，未来放 Zalo 小程序）；员工账号默认角色 sales，只能录单+看自己提交的订单。
7. **录单**：单页表单 + 粘贴解析（每行一条、首个冒号分割、兼容中越文标签）；IMEI 仅粘贴自动提取 15 位数字（扫码拍照功能用户已明确取消）；所有图片上传非必填；门店收款为二维码上传（无开户行字段）。
8. **MDM 监管锁**：不对接接口，仅登记序列号（serial），绑定后展示复制按钮，admin 可改，全程留操作日志。
9. **贷后口径（旧系统 2026-11-22 定版，新系统贷后模块必须沿用）**：应还=每期额×已到期期数；实收=实收全部款项（不含减免）；欠款=逐单 max(0,应还-实收)；提前结清整单剔除统计；设备收回单独归类为违约不算坏账；违约率=进入还款期有欠款订单/进入还款期订单。
