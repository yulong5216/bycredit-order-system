# BY Credit · 越南手机分期录单与订单管理 PRD

> 版本 1.0 · 基于原型验收后的最终拍板
> 产品形态：Web 后台（供业务员/审核/财务/运营使用）+ Zalo 小程序内嵌 H5（供客户查账还款）
> 部署：同一服务器 `byphone.cn`，按路径前缀拆分（见 DESIGN.md）

## 1. 业务范围与不做什么

**做：**
- 业务员录单 → 初审 → 电子签约 → 终审 → 财务放款 → 客户还款 → 贷后管理
- 门店管理（合作/自有、A/B/C/D 评级、正常/冻结）
- 8 角色权限框架（按动作级权限配置）
- MDM 监管锁绑定（双字段：序列号 + IMEI 都必填，准富后台手动操作，系统只记录结果）
- MobiFone 电子签约（人工：下载表格 → 上传 MobiFone → 回填合同号与结果）
- VietQR 三方支付（后端直连，生成二维码 → 客户扫码 → VietQR 回调销账）
- 账单四字段（首付款/分期额/期数/每期金额）+ 每期代客登记 + 账单合并对账
- 财务报税 CSV 导出
- 操作日志（所有人可见，只增不删）

**明确不做：**
- 违约金
- 门店代收
- 商品库/SKU（录单直接选机型和容量）
- 老客户资料复用进件（每次重新提交）
- 准富以外的 MDM 自动绑定/锁机回调（无开放 API）
- MobiFone 自动建合同/短信/签约回调（不提供）
- 投诉管理、回收管理

## 2. 订单状态机（14 态）

```
draft → pending_first → pending_customer_sign → pending_final → approved_final → pending_finance → pending_payout → repaying → closed
           ↓                   ↓                  ↓
    rejected_first         rejected_final      cancelled
                                          ↘ overdue → breach
```

| 状态 | 含义 | 谁能触发 |
|---|---|---|
| draft | 草稿 | 业务员 |
| pending_first | 待初审 | 业务员提交 / 驳回后补件重提 |
| rejected_first | 初审驳回 | 初审 |
| pending_customer_sign | 待客户 MobiFone 签约 | 初审登记上传 |
| pending_final | 待终审 | 客户签约成功且 MDM 已绑定 |
| rejected_final | 终审驳回 | 终审 |
| approved_final | 终审通过待财务 | 终审通过 |
| pending_finance | 财务待审批 | 系统自动流转 |
| pending_payout | 待放款 | 财务审批通过 |
| repaying | 还款中 | 财务录入回单 |
| overdue | 逾期 | 系统定时任务判定到期未还 |
| breach | 坏账 | 财务/贷后手动标记 |
| closed | 结清 | 最后一期还款成功 |
| cancelled | 取消 | 管理员 |

## 3. 8 角色 + 动作权限

| 角色 | 主要动作 |
|---|---|
| admin（管理员） | 全权限 |
| sales（业务员） | 录单、补件重提、查看自己的订单进度 |
| first（初审） | 初审通过/驳回、上传客户资料、登记 MobiFone 上传、回填签约结果、绑定/解绑 MDM、改账单四字段、改首期还款日 |
| final（终审） | 终审通过/驳回 |
| finance（财务） | 审批放款、录入放款回单、代客登记还款、延期、坏账标记、CSV 导出 |
| manager（店长） | 看本店数据、编辑本店资料 |
| aftercare（贷后） | 查看对账、添加对账备注 |
| collector（催收） | 查看逾期/坏账订单 |

权限按动作名配置，集中在 `assets/shell.js` 的 `PERMISSION_GROUPS`。新增角色只需追加条目，不改代码逻辑。

## 4. 账单四字段与修改权限

四字段：`downPayment`（首付款）/ `principal`（分期额，= 售价 - 首付款）/ `periods`（期数）/ `perPeriod`（每期金额）

- 初审**未通过**：初审和管理员可以改
- 初审**已通过**：仅管理员可改
- 所有修改留日志（谁、改前改后、时间）

还款日：直接改首期还款日，后续各期整月后移，原因必填，留日志。

## 5. 支付与还款

### 5.1 三种支付渠道
- **线上QR**：VietQR 二维码扫码支付 → VietQR 回调自动销账
- **其他转账**：银行 App / 电子钱包转账到对公账户 → 代客登记 + 财务对账
- **线下现金**：现金交付 → 代客登记

### 5.2 每期账单代客登记
必填：支付订单号、支付渠道、支付时间。现金/转账渠道不能只填金额就过。

### 5.3 VietQR 二维码
- 为每期账单生成一个短支付码 `P` + 订单号后 8 位（例如订单 N20261114001234501 → `P001234501`）
- 短码传入 VietQR 的 `orderId`（限 13 字符内）
- 转账备注用短码（`content` 限 23 字符、无声调、无特殊符号）
- VietQR 回调短码 → 我们反查订单 + 期次 → 销账

### 5.4 回调幂等
同一个 `transactionid` 只销一次账；金额不符告警；重复回调直接返回 200。

### 5.5 回调丢失兜底
VietQR 未公开交易查询接口，所以兜底策略：
- 定时任务拉 VietQR 商户后台流水（通过他们的导出 API 或爬虫）
- 对比未销账的账单，自动补销 + 日志
- 财务可手动触发对账

## 6. MDM 监管锁

- 双字段都必填：序列号 + IMEI
- 准富后台需短信验证码，无法代登，所以**不在我们系统里绑定/锁机**
- 系统只记录"人工绑定结果"（谁、什么时候、填了什么序列号和 IMEI）
- 解绑必须填原因，留日志
- 准富回调什么都不依赖，我们不假设

---

## 7. MobiFone 电子签约（人工流程）

1. 下载客户资料表格 CSV（客户姓名/证件号/手机号/机型/金额等字段）
2. 在 MobiFone 后台上传表格完成 KYC + 签署
3. 回到我们系统登记表格文件名
4. 客户签署后回填：成功必须填合同号，失败必须填原因
5. 签约成功 + MDM 已绑定 → 转终审；未绑定 → 回到初审
6. 所有次数、合同号、操作人记进日志

## 8. 客户小程序

- 用客户手机号精确匹配订单（`bycredit_customer_phone`）
- 默认读 Zalo 绑定的手机号
- 右上角换绑入口（客户多个手机号可能）
- "我的订单" 列表 + 每期账单状态
- 还款：调后端 `/api/payment/generate` 拿 VietQR 二维码 + `qrLink`，客户扫码支付，VietQR 回调销账后刷新状态

---

## 9. 门店

- 类型：合作店铺 / 自有店铺
- 状态：正常 / 冻结（冻结后不可录新单、不可送财务，存量继续还款）
- 评级：A 正常 / B 影响放款比例 / C 影响放款比例 / D 黑名单
- 自有店铺不签回收协议，但门店合同仍须上传
- 评级/冻结变更必须填原因，留日志

---

## 10. 历史客户风险

审核界面按相同证件号查询历史订单：
- 正常还款中/结清 → 绿色
- 逾期/坏账 → 红色
- 标注"存在历史订单"并列出笔数

## 11. 数据层约定

### 所有操作都记日志
统一结构：
```js
{ id, at, by, role, action, before, after, note }
```
只增不删，所有人可看。

### 财务报税 CSV（UTF-8 BOM）
17 列：订单号、客户名、证件号、手机号、门店、机型、容量、IMEI、订单金额、首付款、分期额、放款金额、已回款、未回款、放款时间、银行回单号、订单状态。
